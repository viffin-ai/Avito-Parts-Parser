# Avito Parts Parser

Небольшой Python-парсер для поиска автомобильных запчастей на Avito по артикулу.

Проект получает поисковую выдачу, извлекает объявления, дополнительно фильтрует их по состоянию и региону, удаляет дубли, сортирует по цене и сохраняет до пяти самых дешёвых подходящих предложений по каждому артикулу в `result.xlsx`.

Изначально проект выполнен как тестовое задание для HONEXAUTO.

## Что реализовано

* поиск нескольких артикулов;
* формирование поискового URL для каждого артикула;
* два источника HTML: прямой запрос и сохранённые страницы;
* парсинг карточек через BeautifulSoup;
* извлечение заголовка, цены, региона, состояния и ссылки;
* преобразование цены в число;
* фильтрация только новых товаров;
* дополнительная проверка региона после получения выдачи;
* исключение объявлений без числовой цены;
* удаление дублей внутри одного артикула;
* сортировка объявлений по возрастанию цены;
* выбор пяти самых дешёвых предложений;
* формирование `result.xlsx`;
* отдельные статусы для успешного результата, пустой выдачи и ошибок;
* тесты основных edge cases.

## Артикулы

В текущем задании используются:

## Структура проекта

```text
avito_parser/
├── input_html/       сохранённые HTML-страницы
├── tests/            автоматические тесты
├── avito.py          формирование URL и получение HTML
├── parser.py         парсинг, фильтрация, дубли и TOP-5
├── excel.py          формирование result.xlsx
├── main.py           основной сценарий запуска
├── pyproject.toml
├── uv.lock
└── README.md
```

Получение HTML отделено от его обработки.

Поэтому один и тот же парсер может работать как с результатом обычного HTTP-запроса, так и с ранее сохранённой HTML-страницей. Это позволяет проверить основную логику даже в случае, если прямой запрос к Avito недоступен.

## Почему выбраны эти технологии

Для HTTP-запроса используется `requests`: для двух поисковых запросов асинхронность или более тяжёлый HTTP-клиент здесь не нужны.

HTML разбирается через `BeautifulSoup`. Для поиска элементов используются в первую очередь атрибуты `data-marker`, а не сгенерированные CSS-классы страницы.

`openpyxl` используется для создания итогового Excel-файла. Pandas для такого объёма данных не требуется: фильтрация, сортировка и дедупликация выполняются обычными средствами Python.

Для управления окружением и зависимостями используется `uv`.

## Установка

Для работы требуется Python 3.10+ и установленный `uv`.

```bash
uv sync
```

## Запуск

Проект поддерживает два режима.

### Live

```bash
uv run python main.py --source live
```

Перед запуском в браузере необходимо открыть Avito и вручную установить:

* регион — Москва и Московская область;
* состояние — новое;
* сортировку — сначала дешёвые.

После этого URL поисковой страницы передаётся программе.

Парсер сохраняет параметры URL, сформированные самим Avito, и меняет поисковый параметр `q` для каждого артикула.

Используется обычный HTTP-запрос. Проект не пытается обходить CAPTCHA, авторизацию, антибот-защиту или другие ограничения сайта.

При успешном запросе HTML дополнительно сохраняется в `input_html/`.

### Сохранённый HTML

```bash
uv run python main.py --source file
```

В этом режиме сетевые запросы не выполняются.

Используются файлы:

```text
input_html/223112R020.html
input_html/233002F700.html
```

Сохранённые страницы не добавляются в публичный репозиторий, так как это объёмные снимки динамической выдачи Avito. Они создаются автоматически при успешном запуске в live-режиме либо могут быть помещены в input_html/ вручную для проверки парсера.

## Как обрабатываются объявления

Для каждого артикула выполняется следующая последовательность:

```text
получение HTML
        ↓
поиск карточек
        ↓
извлечение полей
        ↓
фильтрация
        ↓
удаление дублей
        ↓
сортировка по цене
        ↓
TOP-5
        ↓
result.xlsx
```

### Цена

Из отображаемой цены удаляются пробелы, знак валюты и другие нечисловые символы.

Например:

```text
6 422 ₽
```

преобразуется в число:

```text
6422
```

Если числовую цену получить нельзя, объявление не участвует в выборе пяти самых дешёвых.

### Состояние

В результат попадают только карточки со значением:

```text
Новое
```

Если состояние отсутствует или отличается от `Новое`, объявление исключается.

### Регион

Регион сначала задаётся через интерфейс Avito.

Во время проверки выяснилось, что в фактической выдаче могут встречаться объявления из других регионов, поэтому после парсинга выполняется дополнительная локальная проверка региональной части URL объявления.

Неизвестные и неподходящие значения региона в результат не попадают.

### Дубли

Основным идентификатором объявления используется `data-item-id`.

Если ID отсутствует, в качестве запасного ключа используется ссылка.

Дедупликация выполняется отдельно для каждого артикула.

### Сортировка и TOP-5

После фильтрации объявления повторно сортируются самим приложением по числовой цене.

Даже если сортировка уже выбрана на Avito, итоговый порядок не зависит от порядка карточек в HTML.

После сортировки сохраняются первые пять объявлений. Если подходящих предложений меньше пяти, сохраняются все.

## Результат

После запуска создаётся:

```text
result.xlsx
```

Одна строка соответствует одному объявлению.

В таблице сохраняются:

* искомый артикул;
* поисковый запрос;
* заголовок;
* цена;
* город или регион;
* состояние;
* ссылка;
* место по цене;
* дата и время проверки;
* статус;
* описание ошибки, если она возникла.

Возможные статусы:

* `ok` — объявление успешно обработано;
* `не найдено` — подходящих объявлений нет;
* `ошибка` — страницу получить или обработать не удалось.

## Тесты

Запуск:

```bash
uv run pytest -v
```

Проверяются основные сценарии:

* пустой HTML;
* отсутствующая цена;
* отсутствующее состояние;
* товар не в новом состоянии;
* неподходящий регион;
* удаление дублей;
* сортировка по цене;
* выбор только пяти самых дешёвых объявлений;
* присвоение `price_rank`.

Проверка линтера:

```bash
uv run ruff check .
```

Проверка форматирования:

```bash
uv run ruff format --check .
```

AI использовался как вспомогательный инструмент:

* при подготовке отдельных фрагментов кода;
* для анализа структуры HTML;

* для обсуждения edge cases;
* при подготовке тестов;
* для ревью проекта и README.

Все запросы к Avito, сохранённые HTML-страницы, результаты парсинга, Excel-файл и тесты запускались и проверялись локально.

AI не использовался для обхода CAPTCHA, авторизации, антибот-защиты или других ограничений Avito.

## Сложности при выполнении

Основные сложности были связаны не с самим HTML-парсингом, а с особенностями фактической выдачи:

* некоторые данные расположены не там, где можно было ожидать по старым примерам парсеров;
* местоположение в карточке может отображаться как ближайшее метро, поэтому для проверки города использовалась региональная часть ссылки;
* при поиске с московскими параметрами в выдаче встречались объявления из других регионов;
* живая поисковая выдача меняется между запусками;
* объявление без корректной числовой цены не должно случайно попасть в TOP-5.

Из-за этого фильтрация выполняется повторно после получения HTML, а не полностью полагается на параметры поискового URL.

## Затраченное время

Фактически затраченное время: 3 часа.

Время включало настройку проекта, исследование структуры HTML, реализацию парсинга и фильтрации, проверку реальной выдачи, тесты и подготовку результата.

## Ограничения

* Парсер зависит от HTML-разметки Avito. При изменении структуры страницы селекторы могут потребовать обновления.
* Для определения региона используется информация из URL объявления и консервативная локальная фильтрация.
* Проект не пытается обходить ограничения Avito.
* В проекте нет cookies, токенов, логинов и других секретов.
* Сохранённые HTML позволяют воспроизводимо проверить парсер без обращения к сайту.
